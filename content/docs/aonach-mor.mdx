Aonach Mór is a fictional city-resilience exemplar on real coastal geography. One
signed snapshot of its asset–hazard graph is queried three ways — to **underwrite**
the city, to **harden** it, and, when the surge comes, to **save** it. Every query
below runs the **real query IR** in your browser (as DuckDB SQL over the tile-row
Parquet, the same IR the Rust backend compiles), and every result is computed live,
not canned.

This is the running illustration from the [Introduction](/docs): the resilience
questions a city's responders, planners and insurers actually ask — each lowered
through the real query IR, answered with no backend. The same engine runs at
**real-city scale** — 763,000 buildings served as static Parquet — with that public
demo pending data hosting.

<Callout title="Two corpora, one schema">
Use the **corpus** toggle. *Sample* is a hand-built 10-asset slice — small enough to
read, with the traps spelled out. *Full city* is a **chunked** corpus: geo-partitioned
Parquet files plus a manifest (the file-level zone-map). A query reads the manifest
(KB), prunes to the chunks it needs, registers only those, and range-fetches their
row groups — so a filtered search touches a handful of HTTP ranges, never the corpus.
Total size is therefore unbounded (each file stays under any host cap); the demo
default is modest so the docs build stays quick, and it scales to GBs by adding
chunks. That is the point — **a too-big-to-download corpus, searched where it sits.**
</Callout>

## What each tab shows

- **Concept · Range · List** — `gem ⊑ MUR` walks the GEM taxonomy as a single
  DFS-interval range (all unreinforced masonry, no enumeration) — routed, like every
  other concept, through the **melted concept store**, not any promoted `concept_id` on
  the tile. Heritage, roles and zone are **node-scoped** predicates against that store
  (`concepts_<graphid>`: one row per `(tile, node, concept)`,
  sorted `(node_id, concept_id)`) — so `roles ∋ Shelter` matches *that* node exactly,
  never conflating with heritage or zone the way one crammed `concept_ids` array would.
  A single node can hold several values, so multi-valued facets are just rows. `All[…]`
  intersects the parts by `resource_id`.
- **OnTile vs All** — “built by Lanyon between 1990–2000” must mean *one* retrofit
  event carried all three facts. `OnTile` binds them to a single tile; `All` only
  needs each met *somewhere*, so it keeps the **paper retrofits** — a CR job that
  wasn't accredited plus an accredited job that wasn't CR. On the full corpus that
  gap is thousands of assets.
- **Spatial + Not** — footprints over a two-cell flood extent. The coarse (union-box)
  step admits a superset; the per-cell exact step trims it. There is *no spatial
  extension in the browser*, so this is the on-device path — and negating a coarse
  superset is **refused**, because a flooded shelter must never be reported dry.
- **Zone map** — the point of the whole exercise. On the full city it draws each
  **chunk's geo zone from the manifest** (KB) — *no coordinates are downloaded*. Click
  to move the query box: the lit chunks are the only files a spatial query fetches; the
  rest are pruned from the manifest, never requested. Within a fetched chunk, its own
  footer prunes row groups again — two tiers of pruning. The chunks are Morton-clustered,
  so a *spatial* query hits a handful. A facet filter (heritage / role / zone) can't
  prune geo chunks at all — it reads the **separate melted concept store**, its own
  `(node_id, concept_id)`-sorted axis, range-fetched to the matching block and joined
  back by `resource_id`. Each axis (geo, concept) is its own store with its own sort
  order and zone-map, joined by `tile_id`/`resource_id` — which is why you rarely need a
  second co-clustered copy. Grow the corpus to GBs and the query still fetches only the
  block it needs: **cost is O(query), not O(corpus).**
- **cited_by cascade** — the edge table read backwards: pick a substation, see every
  asset that depends on it.
- **Base ⊕ overlay** — live damage arrives as a separate layer, composed at query
  time; the signed base is never mutated.
